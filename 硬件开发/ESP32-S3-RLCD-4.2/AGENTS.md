# ESP32-S3-RLCD-4.2 子项目约束

本文件约束本目录内的固件、硬件资料和实机操作。

- 本机依赖只使用 MacPorts，不得使用 Homebrew 或执行 `brew` 命令。
- ESP-IDF 固定使用与 Waveshare 官方示例匹配的 5.5.2；升级前必须先验证官方示例和本项目固件。
- 加载 ESP-IDF 前必须确认其虚拟环境使用 MacPorts Python 3.12；不得因系统中的其他 Python 版本自动新建平行环境。
- `managed_components/` 出现带空格编号的冲突副本时不得继续生成烧录候选；先隔离可再生目录，再从 `dependencies.lock` 恢复干净依赖。可复现验证使用独立构建目录，不在同一依赖目录上反复执行清理下载。
- BLE UUID、协议版本和状态字段必须与 Mac 端 `HardwareMonitorBLEProtocol.swift` 完全一致；修改任一端时必须同步修改另一端并完成协议单元测试和真实连接验收。
- 硬件屏是低频快照屏，不显示或传输实时占用并发、活动任务、运行数和等待数等对延迟敏感的业务指标；只保留累积汇总、配额快照、近期任务结果和解释数据停滞所需的设备健康信息。
- 四个监控页面必须按各自数据语义设计信息层级，主数值优先上移并使用大字号；不得用统一卡片矩阵或装饰性分隔线套用所有页面。次要信息不得为填满空间而放大；可用页头微型状态等方式紧凑表达，不影响判断的字段应直接省略且不传输。设备页默认使用一个大状态和紧凑信息行，除非后续真实数据语义要求改变。
- 全反射屏不得显示需要持续重绘才能保持准确的相对时间；在 RTC 时间显示完成前，用微型 `SYNCED`、`STALE`、`OFFLINE` 或 `NO DATA` 状态表达更新情况，不为更新文字引入定时刷屏。
- 真实监控数据只允许在实体长按授权后建立的加密持久绑定上传输；未绑定链路只允许进行不含业务数据的版本握手，任何链路都不得传输凭据。
- 串口必须动态发现，不得硬编码 `/dev/cu.usbmodem*` 的具体编号。
- 本板原生 USB 串口在主机打开连接时可能触发一次 `USB_UART_CHIP_RESET`；串口验收必须区分这种主机诱发复位与固件自发重启，不得把打开监视器后的单次复位误判为运行时崩溃或重启循环。
- 首次写入前必须完成 16 MB Flash 备份、校验和官方恢复固件留存；未完成前不得擦除或覆盖 Flash。
- 设备专属 Flash、MAC、序列号和私有日志不得提交；临时材料放入 `tmp/yyyy.mm.dd/`。
- 固件先完成编译，再烧录并核对串口日志和屏幕结果；不得用编译成功代替实机验证。
- 多节 18650、RTC 电池和外部供电必须先确认接口、电压、保护和极性，不得直接试接。

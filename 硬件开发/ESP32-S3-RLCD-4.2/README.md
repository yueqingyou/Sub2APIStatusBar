# ESP32-S3-RLCD-4.2 监控屏

本目录保存 TokenRouter Monitor 独立硬件监控屏的固件、公开硬件文档和验收记录。

当前源码候选和实物运行固件为 `0.9.4`。它保留 `0.8.4` 的四页低频快照、电量采样和独立 BLE 升级链路，并使用监控协议 6：macOS App 可按北京时间配置夜间 Deep-sleep，默认 `23:30–07:30`。设备只在收到 Mac 的有效北京时间后启用计划；进入休眠时屏幕、BLE 数据同步和固件升级均离线，由板载 PCF85063 RTC 在计划结束时唤醒，实体 `KEY` 可提前唤醒并只跳过当前窗口。休眠期间修改的设置会在下次连接后生效。

常连低功耗基线使用 ST7305 `1 Hz` LPM、ESP32-S3 `40–160 MHz` 动态降频、自动 Light-sleep 和 NimBLE modem sleep；主循环由固定 `20 ms` 轮询改为事件唤醒，未使用的 SHTC3 进入休眠，PCF85063 `CLKOUT` 关闭。已绑定设备断线后先以 `20 ms` 间隔快速广播 30 秒，再切到 Apple 建议档位中的 `1022.5 ms`；首次配对窗口仍保持快速广播。BLE 低功耗时钟继续使用主晶振，没有假设或增加外部 32 kHz 硬件。

两个各自从 `sdkconfig.defaults` 生成新 `sdkconfig` 的 ESP-IDF 5.5.2 目录，生成了逐字节一致的配置、bootloader、分区表、OTA 元数据和 693,696 字节 `0.9.4` 应用镜像。应用 SHA-256 为 `9ac18db3ac2f6978bb22fcd2623b839c29d9f0b5e51af28eaa7c5c80b36e283a`，App 内置资源已完成同值校验。隔离候选 App 经原有加密绑定把实物从 `0.9.3` 升级到 `0.9.4`：传输到 `100%`，设备断线重启，原绑定加密回连并回读 `0.9.4 · 已完成`。

USB 串口和 JTAG 联合定位了反复重连的原因：唤醒引脚经 `rtc_gpio_init()` 切换到 RTC IO 域后，入睡前稳定性检查和最后瞬时检查仍误用普通 `gpio_get_level()`。`0.9.4` 将这两处改为 `rtc_gpio_get_level()`，不改变 RTC、备用定时器和 `KEY` 的既定唤醒政策。北京时间 `19:05–19:08` 的短时窗口中，设备只在 `19:05:48` 断开一次，随后 133.118 秒内不可发现、133.304 秒内未连接；唤醒后回报 `rtcInterrupt`，恢复协议 6 加密绑定连接并回读 `0.9.4`。默认 `23:30–07:30` 随后已恢复并重新下发。

`0.8.4` 是上一个完整屏幕与电量基线：实物先从 `0.7.0` 经已绑定加密 BLE 升级到 `0.8.1`，再依次升级到 `0.8.2`、`0.8.3` 和 `0.8.4`，四次都没有执行 USB Flash 写入。`0.9.4` 已完成最终镜像 BLE 升级、重启、加密回连、真实不可发现休眠和 RTC 唤醒验收。实体 `KEY` 提前唤醒、备用定时器单独唤醒、完整默认过夜窗口、快慢广播的精确射频时序、屏幕 `1 Hz` 模式的物理确认、电压万用表校准和整板电流仍未实测，因此不宣称功耗降幅或续航结果。

- `HARDWARE_MONITOR_DESIGN_ZH.md`：整体方案、硬件决定和实施进度；
- `firmware/`：正式 ESP-IDF 固件；
- 设备专属 Flash 备份、构建缓存和临时日志放入 `tmp/yyyy.mm.dd/`，不得提交。

本机 ESP32 工具和依赖只使用 MacPorts。固件使用 ESP-IDF 5.5.2；屏幕只在切页、链路状态或实际显示值变化时刷新，相同数据不会重复重绘。独立离线检查关闭时，设备仍会按当前页同步周期延迟判定 Mac 离线。绑定使用 LE Secure Connections Just Works，有加密但没有 MITM 认证；实体按键和限时窗口是首次授权边界。正式安装的 `0.1.37` App 未被覆盖；隔离候选 App 在恢复并下发默认计划后已停止。下一阶段是实测实体 `KEY` 提前唤醒、备用定时器路径、完整过夜窗口、快慢广播时序和整板运行/休眠功耗，再根据测量结果确定电池包与外壳。

ST7305 显示适配层基于 Waveshare 的 Apache-2.0 示例修改；原始版权、许可证副本和修改声明保存在 `firmware/components/u8g2_st7305/`。

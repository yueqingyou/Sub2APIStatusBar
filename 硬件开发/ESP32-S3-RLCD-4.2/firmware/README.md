# TokenRouter Monitor 固件

本目录是 ESP32-S3-RLCD-4.2 的正式 ESP-IDF 固件。当前源码候选为 `0.7.0`，包含概览、任务、配额和设备四页；QUOTA 页显示五小时和七天剩余容量百分比，以及各窗口最早下一次重置的剩余时长快照，固定保留 `D`、`H`、`M` 三段，不再显示或接收 Normal Account。普通页面不再常驻显示页码、按键教程和重复链路状态。该候选已在 ESP-IDF 5.5.2 下完成双目录可复现构建，正式应用镜像为 630,560 字节；实机已从 USB 引导版 `0.6.9` 通过既有加密绑定完成 BLE 升级、校验、重启回连、OTA 0 回读和 `VALID` 状态确认。短按板载 `KEY` 依次切页，长按 1.5 秒开启 60 秒 BLE 配对窗口。电池测量和定时休眠尚未启用。

未绑定且配对窗口关闭时，设备不广播项目服务。长按允许一台 Mac 使用 LE Secure Connections Just Works 建立加密绑定；已有绑定不会被普通长按单方删除，绑定保存在 NVS，重启后可自动恢复。由于开发板没有密码或数字确认输入，该模式不提供 MITM 认证；实体长按和 60 秒窗口是授权边界。

安全链路的监控协议版本为 4。握手只确认监控数据兼容性；随后 Mac 根据设备当前页发送低频脱敏快照，不发送实时并发、活动任务、运行数或等待数。QUOTA 的重置剩余时长由 Mac 在完整同步时计算，固件不会在同步之间自行倒计时或为此定时重绘。独立轻量心跳只更新 Mac、网络和 TokenRouter 在线状态；关闭独立检查时，离线超时自动跟随当前页的完整同步周期。设备不会接收凭据、账号身份或原始 API 响应。相同数据仍会更新在线计时，但不会触发整屏重绘。

固件升级协议独立固定为版本 1，因此新版 App 即使遇到旧监控协议也能进入仅升级模式。升级只接受已绑定且已加密的 BLE 连接；Mac 发送目标版本、镜像大小和完整文件 SHA-256，固件把数据写入非运行 OTA 分区，并在结束时校验接收长度、SHA-256、ESP 镜像结构、项目名和目标版本。升级界面只显示阶段、进度和保持供电提示。校验通过后切换启动分区并重启，新固件完成屏幕与 BLE 初始化后才取消回滚；首次启动失败时 bootloader 回到上一分区。

GATT 服务表使用独立持久化版本。新增或移除服务和特征时，设备通过标准 Service Changed 指示使已绑定 Mac 的缓存失效，并在收到确认后记录新版本；Mac 收到服务失效回调后自动重新发现。升级服务表不要求删除绑定、重新配对或再次 USB 初始化。

从旧单应用分区迁移时只需一次 USB 初始化：写入 `0x0000` bootloader、`0x8000` 分区表、`0x10000` factory 应用和 `0x610000` OTA 元数据，不执行全片擦除，也不覆盖从 `0x9000` 开始的 NVS，因此保留蓝牙绑定。用于验证真实蓝牙升级的 USB 引导镜像版本为 `0.6.9`；App 正式资源始终使用 `0.7.0`，不得混用。完成这次初始化后，日常固件升级只通过 macOS App 的 BLE 操作进行。

固件固定使用 ESP-IDF 5.5.2，并通过 ESP Component Registry 固定使用 `nixy4/u8g2` 0.1.4。ST7305 初始化参数和屏幕引脚基于 Waveshare 官方示例；当前分区布局使用 2 MiB factory、2 MiB OTA 0、2 MiB OTA 1 和独立 OTA 元数据，同时保留既有 NVS。

`components/u8g2_st7305/` 基于 Waveshare 的 Apache-2.0 示例修改，目录内保留原始版权、许可证副本和修改声明。通过 ESP Component Registry 获取的 U8g2 仍适用其自身许可证。

构建前先加载基于 MacPorts Python 3.12 的 ESP-IDF 5.5.2 环境，然后在本目录执行 `idf.py build`。构建目录、自动下载的组件和本机 `sdkconfig` 不提交；从旧版固件切换后，应移走旧 `sdkconfig` 让 `sdkconfig.defaults` 重新生效。组件版本由 `idf_component.yml` 和 `dependencies.lock` 共同固定。顶层 CMake 会拒绝带空格编号的组件冲突副本，生成烧录候选时仍需使用两个独立构建目录比较 bootloader、分区表、OTA 元数据和应用镜像。正式 `0.7.0` 构建完成后，从仓库根目录运行 `./scripts/update-hardware-firmware-resource.sh <构建目录>` 更新 App 资源，再运行 `./scripts/verify-hardware-firmware.sh` 复核清单与 SHA-256。

# ESP32-S3-RLCD-4.2 子项目约束

本文件约束本目录内的固件、硬件资料和实机操作。

- 本机依赖只使用 MacPorts，不得使用 Homebrew 或执行 `brew` 命令。
- ESP-IDF 固定使用与 Waveshare 官方示例匹配的 5.5.2；升级前必须先验证官方示例和本项目固件。
- 加载 ESP-IDF 前必须确认其虚拟环境使用 MacPorts Python 3.12；不得因系统中的其他 Python 版本自动新建平行环境。
- `managed_components/` 出现带空格编号的冲突副本时不得继续生成烧录候选；先隔离可再生目录，再从 `dependencies.lock` 恢复干净依赖。可复现验证使用独立构建目录，不在同一依赖目录上反复执行清理下载。
- 正式固件候选的每个独立构建都必须指定一份不存在的新 `SDKCONFIG`，由 `sdkconfig.defaults` 生成；不得复用或复制开发目录中的已生成 `sdkconfig`。比较两份镜像前必须先确认两份 `sdkconfig` 逐字节一致，且必需的电源管理与 Tickless Idle 选项已实际启用。
- BLE UUID、监控协议版本和状态字段必须与 Mac 端 `HardwareMonitorBLEProtocol.swift` 完全一致；固件升级协议必须独立版本化并保持向后兼容，使新版 App 在监控协议不兼容时仍可进入仅升级模式。修改任一端时必须同步修改另一端并完成协议单元测试和真实连接验收。
- GATT 服务或特征增删时必须提升持久化服务表版本，向既有绑定发送 Service Changed 指示，并在收到确认后持久化新版本；Mac 端必须让失效服务自动重新发现。不得依赖删除绑定、重新配对或固定设备地址来掩盖缓存问题。
- 状态通知的前 16 字节必须保持为跨监控协议版本的固定升级兼容前缀；固件版本、当前页、升级协议、升级状态、错误码和接收字节数的既有偏移不得改变，新增状态只能追加在其后。
- 硬件屏是低频快照屏，不显示或传输实时占用并发、活动任务、运行数和等待数等对延迟敏感的业务指标；只保留累积汇总、配额快照、近期任务结果和解释数据停滞所需的设备健康信息。
- 不改动现有硬件时，显示控制器固定使用 `1 Hz` 低功耗刷新；BLE 已绑定设备断线后先以 `20 ms` 间隔快速广播 30 秒，再固定使用 `1022.5 ms`，首次配对窗口仍保持快速广播。常连阶段允许使用 ESP-IDF 动态降频、自动 Light-sleep 和 NimBLE modem sleep，但不得改用当前硬件未确认存在的外部 32 kHz 晶振，也不得在缺少整板实测时宣称具体功耗或续航提升。
- 夜间 Deep-sleep 计划固定按北京时间解释，默认 `23:30–07:30`，并由 macOS App 配置和校时。休眠期间屏幕、BLE 数据同步和固件升级均离线；RTC 在计划结束时唤醒，实体 `KEY` 可以提前唤醒并只跳过当前休眠窗口。设备尚未收到 Mac 的有效北京时间前不得自动休眠，休眠期间修改的设置只能在下次连接后生效。
- 深度休眠唤醒引脚经 `rtc_gpio_init()` 切换到 RTC IO 域后，在 `rtc_gpio_deinit()` 前必须使用 `rtc_gpio_get_level()` 读取电平；不得用普通 `gpio_get_level()` 作为入睡前稳定性判断或瞬时告警判断。该路径修改后必须用断开、整段不可发现、唤醒原因和加密回连四项实机证据验收。
- 四个监控页面必须按各自数据语义设计信息层级，主数值优先上移并使用大字号；不得用统一卡片矩阵或装饰性分隔线套用所有页面。次要信息不得为填满空间而放大；可用页头微型状态等方式紧凑表达，不影响判断的字段应直接省略且不传输。设备页默认使用一个大状态和紧凑信息行，除非后续真实数据语义要求改变。
- 设备自身状态必须来自板载传感器或固件真实状态；电量使用经校准的板载 ADC 电压估算，不得由 Mac 推断、使用固定值或伪装充电状态。电量百分比必须在四个普通页面的同一页头位置显示，设备页另行显示实测电压；采样周期由 Mac 设置独立配置并通过监控协议下发，固件只接受 5 分钟至 1 天的低频范围、每次采样后释放 ADC，且相同显示值不得重绘。不得加入运行时长、倒计时等会为了保持表面准确而周期刷新的次要字段。
- 固件界面只显示当前阶段、进度以及供电或恢复所必需的短提示；正常页面不得常驻页码、按键教程、重复品牌名、重复链路状态或仅用于解释布局的文字。
- 配额页可以显示 Mac 完整同步时计算的重置剩余时长快照，但固件不得在两次完整同步之间自行倒计时或为此定时重绘；其它更新时间继续使用微型 `SYNCED`、`STALE`、`OFFLINE` 或 `NO DATA` 状态表达，不显示“几分钟前”等持续变化文字。
- 真实监控数据只允许在实体长按授权后建立的加密持久绑定上传输；未绑定链路只允许进行不含业务数据的版本握手，任何链路都不得传输凭据。
- 串口必须动态发现，不得硬编码 `/dev/cu.usbmodem*` 的具体编号。
- 本板原生 USB 串口在主机打开连接时可能触发一次 `USB_UART_CHIP_RESET`；串口验收必须区分这种主机诱发复位与固件自发重启，不得把打开监视器后的单次复位误判为运行时崩溃或重启循环。
- 首次写入前必须完成 16 MB Flash 备份、校验和官方恢复固件留存；未完成前不得擦除或覆盖 Flash。
- 首次 OTA 初始化必须保留现有 NVS，只写入回滚 bootloader、双 OTA 分区表、factory 应用和 OTA 元数据。后续固件只允许通过已绑定加密 BLE 链路写入非运行 OTA 分区，校验完整镜像 SHA-256、项目名、目标版本和 ESP 镜像结构后再切换启动分区；新固件完成显示与 BLE 初始化后才可确认取消回滚。
- App 内置固件必须从两个独立目录逐字节一致的正式构建生成，并通过 `Resources/HardwareFirmware/ESP32-S3-RLCD-4.2/manifest.json` 记录型号、固件版本、监控协议、升级协议、大小和 SHA-256。不得把仅用于 USB 初始化的较低版本引导镜像复制为 App 正式资源。
- 设备专属 Flash、MAC、序列号和私有日志不得提交；临时材料放入 `tmp/yyyy.mm.dd/`。
- 固件先完成编译，再烧录并核对串口日志和屏幕结果；BLE OTA 还必须从较低版本实机完成传输、校验、重启、回连和目标版本确认，并检查失败回滚路径，不得用编译成功或 USB 写入代替蓝牙升级验收。
- 多节 18650、RTC 电池和外部供电必须先确认接口、电压、保护和极性，不得直接试接。
